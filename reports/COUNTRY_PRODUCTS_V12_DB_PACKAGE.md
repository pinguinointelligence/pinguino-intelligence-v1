## Sanctioned write path (modeled on scripts/seed-staging-canonical-country-milk.mjs)

1. Pre-flight (read-only): every planned GTIN is still absent from `products`/`product_variants`, every planned route has no active primary, every route country exists in `catalog_market_countries`. Any mismatch stops the run before the first write.
2. `gellatti_submit_product_request_v1` (QA Pro account, `p_market_country_code` = first route country, idempotency key `gellatti-v12-pr-ing:<productKey>`). An `existing_product` answer stops that product.
3. `gellatti_admin_product_request_action_v1` `START_REVIEW`, then `ADMIN_EVIDENCE_PATCH` with the workbook evidence (declared values only — ESTIMATED values are never sent as label data).
4. `preview_product_duplicates_v1`; a candidate with the same GTIN stops the product, a different-GTIN candidate is recorded as `duplicateDecision: different` with distinguishing evidence.
5. `catalog-submit` (`source: admin`, `requireApprovalReady: true`, idempotency `product-request:<requestId>:approve-v12`, `market` = first route country). `approval_not_ready` writes no product (fail-closed) and the product is reported, not retried with other data.
6. `APPROVE_LINK`, then one `product_canonical_slot_reviews` row for the base-slot PI (version-bound).
7. `gellatti_admin_catalog_action_v1` `ADD_MARKET` for each further route country (same variant).
8. `country_product_slot_assignments` `PRIMARY_DEFAULT` per route. The script refuses to replace or deactivate any existing assignment.

## Rollback

Every step goes through an audited RPC or an RLS-guarded table; nothing is deleted. The apply run prints a ledger of every id it created — keep it.

1. Routes: `update public.country_product_slot_assignments set active = false, approval_reason = 'rollback: <reason>' where id = <assignment id>` as a CATALOG admin (the validation trigger re-stamps approved_by/approved_at). Deactivated rows stay for audit.
2. Slot reviews: `update public.product_canonical_slot_reviews set active = false, approval_reason = 'rollback: <reason>' where id = <review id>`.
3. Extra markets: `gellatti_admin_catalog_action_v1(<product id>, 'REMOVE_MARKET', {"market": "<ISO2>", "reason": "rollback"})`.
4. Products: `gellatti_admin_catalog_action_v1(<product id>, 'UNPUBLISH', {"reason": "rollback"})` hides the product and is reversible with `PUBLISH`. `RETIRE` runs the sanctioned `ingest_product_v1` retire operation and is final. An EAN keeps its single `product_variants` row forever, so prefer UNPUBLISH if the product may come back.
5. Requests: approved requests stay APPROVED (terminal history). A request whose approval returned `approval_not_ready` stays open; close it with `REJECT` and a reason.
6. Side rows (request events, notifications, the requester’s favourite, audit rows) are history and are not removed.
