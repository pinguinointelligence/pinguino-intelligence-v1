# Batch Rescue — production contract

Checked: 2026-08-09

## Safety invariants

1. Engine formulas, target bands and Mapper values are unchanged.
2. Forecast = confirmed physical actuals + pending production targets.
3. A confirmed physical amount is a lower bound for every candidate.
4. Only candidates generated by the existing correction solver and rerun by the existing Engine may be shown.
5. Unverified, fallback or estimated target profiles are not described as a verified rescue.
6. Machine capacity is respected.
7. An impossible outcome contains no invented grams and no Apply action.

## Customer outcomes

Only valid outcomes are shown.

### `Skoryguj pozostałe`

- Solver context: planning.
- Confirmed lines carry `actual_grams` and `already_added`; they cannot be reduced.
- Pending lines may change.
- Candidate is exposed only when final mass remains within 0.1 g of the original target and the Engine result is native-safe.

### `Powiększ partię`

- Solver context: `actual_batch`.
- Every correction action must be positive add-only.
- Candidate must be larger than the original batch, within capacity and native-safe.
- UI wording is intentionally `najmniejsza znaleziona, zweryfikowana partia`, not a mathematical global-minimum claim. The current solver does not prove the global minimum.

### `Zostaw tak`

Shown only when the expected completed batch has:

- zero native Engine violations;
- no category/temperature fallback or estimated band;
- valid technical fit;
- no capacity failure.

### `Brak możliwej korekty`

Shown when no candidate satisfies all invariants. No grams or fake ideal state are displayed.

## Instruction language

- Positive change: `Dodaj jeszcze +X g`.
- Pending-plan decrease: shown as a new target for a not-yet-added row, never as removing material.
- Full final totals remain in row targets; rescue copy shows only the change still required.
- Solver-created additions are kept as explicit new production lines and enter final actual mass and label data.

## Apply boundary

A rescue candidate applies only to `ProductionSession.targetGrams` and solver-created production lines. It does not mutate:

- the saved recipe;
- the recipe draft;
- already confirmed physical mass;
- global Engine configuration;
- Mapper data.

## Unsupported branches

Mid-run shortage/substitution and topping stage routing remain pink. Existing substitute preview refuses recipes with actuals and does not carry sufficient canonical/allergen evidence. That flow must not be adapted by resetting the vessel to a clean recipe.

## Future server contract

A server preview/apply should be bound to:

- run ID and revision;
- physical confirmation fingerprint;
- proposed final input fingerprint;
- Engine/config/Mapper versions;
- idempotency key.

Any new confirmation, correction, substitution, machine/serving change or reload conflict must invalidate the preview. Undo may revert unconfirmed instructions only; it must never rewind a confirmed physical event.
